# 도메인 용어집: ZeroHR — 실시간 HR 리포트

이 하네스의 모든 에이전트·스킬·스키마·산출물 경로는 이 문서의 용어만 사용한다.
용어를 바꾸면 관련 이름도 함께 바꾼다 (harness 스킬의 리네임 절차 참조).
데이터 컬럼·JSON 필드의 정확한 정의는 `.claude/DATA_CONTRACT.md`가 정본이다.

## 회사 컨텍스트

| 용어 | 정의 | 표기 | 비고 |
|------|------|------|------|
| Zero Company | **agent-native HR SaaS 스타트업.** 인간 없이 에이전트로만 동작하는 회사 OS 위에서 운영되며, 사람은 직원이 아니라 고객·오너로만 존재한다 | `zero-company` | 형상 정본은 사용자가 제공하는 md(`zero-company/`). 이 하네스가 곧 회사의 운영 조직이다 |
| 제품 포지션 | Workday처럼 HR 운영을 지원하되, **에이전트가 데이터 통합·클린징·분석·리포트 배포까지 직접 수행**한다. HRIS를 대체하지 않고 그 위의 리포트·예측 계층을 맡는다 | `product-position` | |
| ZeroHR | Zero Company의 1호 제품명 — 실시간 HR 리포트(인원 통계 + 조직별 인원 예측 + 권한별 대시보드 + 월초 리포트) | `zerohr` | 회사명이 아니라 제품명. 리네임 시 이 행만 고치면 된다 |
| 고객사 | ZeroHR 서비스를 받는 (사람이 있는) 회사. Build Day 데모의 고객사는 가상 기업 **㈜온다테크**(IT 서비스, 현원 406명) | `client` | 리포트의 독자(경영진·HR·경영기획팀)는 고객사의 사람 |
| 에이전트 조직 | Zero Company의 직원 명부. `.claude/agents/`의 정의 파일이 곧 조직도 | `agent-org` | 채용 = 에이전트 정의 추가, 교체 = 정의 수정 |
| 결정 기록 (DR) | 말로 하는 결정은 없다 — 모든 결정은 문서로. 제안/근거/옵션/기본안/기한/fallback | `decision-record` | 경로 `zero-company/DR-*.md` |
| 기대 효과 | 이 하네스가 기능적으로 보장해야 하는 4가지: ① 월 리포트 수작업 → 완전 자동화(리소스 80% 절감) ② 경영진 실시간 인원 현황 조회 ③ 인력계획 선제 대응 ④ 월간 리포트 자동 생성·배포 | `expected-effects` | 각 효과의 증빙 산출물은 DATA_CONTRACT §8 |
| 세션 실행 제약 | Build Day 세션(Claude Code)에서 외부 발신·영구 스케줄 등록은 사용자 승인이 필요하다. 이는 **Zero Company 설계가 아니라 실행 환경의 제약**이므로 산출물은 "발송 준비 완료" 상태까지 만든다 | `session-constraint` | 프로덕션에서는 에이전트가 직접 발송 |

## 관계

- 인원현황 마스터는 임직원을 여러 명 갖고, 각 임직원은 조직 체계의 팀 하나에 속한다
- TO 계획은 팀마다 하나이며 특정 월에 유효하다
- 퇴사 예정자는 마스터에 있는 재직자를 가리키고, 입사 예정자는 마스터에 없다
- 정제 데이터는 원천 데이터와 클린징 로그로 재구성 가능해야 한다 (감사 추적)
- 인원 통계·월말 인원 예측·이직 리스크는 모두 정제 데이터에서만 계산한다 (원천에서 직접 계산 금지)
- 월말 인원 예측은 TO 계획과 결합해 TO 과부족을 만든다
- 리포트 뷰 3종은 같은 통계를 다른 권한으로 본다 — 숫자가 뷰마다 달라지면 결함이다
- 월초 리포트는 대시보드와 같은 통계에서 만든다
- 페르소나 하나에 제품 하나가 대응하고, 세 제품은 공통 데이터 계층 위에 페르소나 전용 파생 데이터(급여 마감·온보딩 계획)를 얹는다
- 니즈 데이터가 먼저 나오고, 제품은 그 fit 기준으로 만들고, 제품 비교는 같은 니즈 데이터로 채점한다

## 소리내어 검증 (핵심 시나리오)

4. "급여 담당의 니즈 데이터가 '일할 계산 대상'을 요구하면, 급여 마감이 당월 입·퇴사자를 뽑고 ZeroHR Payroll이 그것을 보여준다."
5. "온보딩 담당의 니즈 데이터가 '신설팀 일괄 온보딩'을 요구하면, 온보딩 계획이 AI에이전트팀 입사 예정자 3명을 묶고 ZeroHR Onboard가 체크리스트를 보여준다."

1. "원천 마스터의 부서 표기가 조직 정규화를 거쳐 팀 코드가 되면, 인원 통계가 팀 단위로 집계된다."
2. "기준일 현원에 입사 예정자를 더하고 퇴사 예정자를 빼면 월말 인원 예측이 되고, TO 계획과 비교하면 TO 과부족이 된다."
3. "경영진 뷰는 본부 단위 TO 과부족을 보고, HR 뷰는 같은 숫자를 팀·개인 단위로 본다."

## 규칙 (정책)

| 규칙 | 적용 대상 | 정책 스킬 |
|------|----------|----------|
| 개인 식별 정보(성명·생년월일)는 HR 뷰 밖으로 나가지 않는다. 경영진·경영기획 뷰와 월초 리포트는 집계 또는 사번만 사용한다 | 리포트 뷰, 월초 리포트, 이직 리스크 | `pii-minimization-policy` |
| 모든 집계 수치는 정제 마스터에서 독립 재계산으로 대사되어야 하며, 뷰·리포트 간 같은 지표는 같은 값이어야 한다 | 인원 통계, 예측, 대시보드, 월초 리포트 | `reconciliation-policy` |
| 클린징은 원천을 덮어쓰지 않는다. 보정은 로그로 남기고 규칙으로 못 고치면 미해결로 분리한다 | 클린징 | `reconciliation-policy` (감사 추적 조항) |
| 예측·리스크는 가정을 명시하고, 불확실한 수치는 범위 또는 시나리오로 낸다 | 월말 인원 예측, 이직 리스크 | `reconciliation-policy` (가정 명시 조항) |
| 월초 리포트는 에이전트가 생성·발송한다. Build Day 세션에서는 세션 실행 제약으로 "발송 준비 완료(초안+수신자+일정)"까지 만들고 실제 발송은 사용자 승인 후 | 월초 리포트 | (세션 실행 제약 — CLAUDE.md) |

## 제외 — 이 하네스가 다루지 않는 것

- 급여액·보상·평가: HRIS 본연의 기능이며 ZeroHR은 리포트 계층만 담당 (급여 마감은 "누가 대상인가"만 다룬다)
- 채용 파이프라인(공고·면접): 입사 예정자는 "입사일 확정" 이후만 다룬다
- 근태·휴가 일단위 기록: 휴직 여부만 상태로 다룬다
- 이직 리스크의 ML 학습 모델: 데모는 규칙 기반. 학습형 모델은 고객사 이력 데이터가 쌓인 뒤
