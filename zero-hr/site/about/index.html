제품

세 페르소나의 질문이 다르므로 시안을 세 개 만들고, 세 심판이 각자의 루브릭으로 채점한 뒤 하나로 합쳤습니다.

인사 총괄 · head-of-hr

Insight

실시간 HR 리포트. 권한별 뷰 4종(경영진·HR·경영기획·조직장), TO 과부족, 월말·다음 달 예측, 이직 리스크, 데이터 품질.

열기

급여 담당 · payroll

Payroll Close

월말 급여 마감 보드. 급여 대상 인원(기준일·월말), 일할 계산 대상, 휴직 처리 구분, 계약 만료, 오류 위험, 체크리스트. 금액은 다루지 않습니다.

열기

온보딩 담당 · onboarding

Onboarding

입사 예정자 온보딩 보드. 주차별 타임라인, 조직 배치·버디, 체크리스트, 90일 코호트, 1년 미만 이탈률.

열기

통합 제품

심판 결과로 승자 골격에 차점 제품의 강점을 흡수한 하나의 제품. 역할 탭 6종.

기존 시스템 연동

Function Call

급여·온보딩·인사 총괄 시스템의 agent가 도구로 호출합니다. 도구 18개, HTTP·MCP 서버, 정적 스냅샷.

카탈로그 payroll · onboarding · insight

제품 비교 — 심판 3명

제품 비교 대기 중 — product-judge 실행 후 --product comparison --embed로 갱신됩니다.

상세 채점 과정(루브릭 항목·앵커·mustFix)은 채택 근거 페이지에 있습니다.

Zero Company OS — agent 4역할

데이터 통합 → 클린징 → 분석(통계·예측·리스크·급여·온보딩) → 배포(권한별 화면·월초 리포트·Function Call) → owner agent가 종합하고 사람이 승인합니다.

모든 단계는 핸드오프 로그(시도·근거·실패·검증·인계점)를 남기고, 외부 발송·배포는 사람 승인을 거칩니다.

이 화면의 범위

구현됨

  • 원천 생성·클린징·통계·월말 예측·이직 리스크·급여 마감·온보딩 계획 스크립트와 테스트
  • 역할 전환·조직 선택·시나리오 플래너(가정 표기, 저장 안 함)
  • Function Call 도구 18개 · HTTP/MCP 서버 · 정적 스냅샷

목업 · 준비 완료

  • 월초 이메일: 발송 명세만 ready-to-send, 수신자는 가상 주소
  • Supabase 실시간 갱신: config.js가 있을 때만 덮어씀
  • 온보딩 체크리스트 상태: seed 고정 가상 데이터

승인 대기

  • 실제 발송, GitHub·Supabase·Vercel 배포
  • 채용 가속·TO 재검토 권고의 채택

역할 뷰는 표시 필터이며 접근 통제가 아닙니다(행 단위 보안은 고도화 항목). 데이터는 agent가 생성한 가상 HR 데이터입니다.
